# OpenCDA-MARL — agent guide

Cooperative multi-agent reinforcement learning for autonomous driving on
CARLA/SUMO. This file is the single entry point for coding agents and human
contributors alike; there is no per-tool twin, so every tool reads the same
content.

**Maintainer overlay**: a `.agents/` directory exists only on the
maintainer's source line. When present, read `.agents/index.md` before
anything else — it adds maintainer-specific rules and takes precedence. Its
absence means this file plus `docs/agents/` is the whole rule set.

## Owner gates

Ask the maintainer only for these; everything else proceeds once its checks
pass, and is reported.

- **Publication and releases**: moving `main`, tagging, bumping the declared
  version, publishing docs or packages, and anything that makes unreleased
  material public.
- **Shared history**: force-pushing, rewriting or deleting a shared branch,
  tag or archive ref. Deleting your own landed task branch is not gated.
- **Direction**: a change to a seam in
  [Agent Workflow](docs/agents/workflow.md#the-seams), to the public API, or
  to a rule in this file.
- **What automation cannot verify**: visual UI, interaction logic, a live
  CARLA run you cannot start. Say in the pull request what was not verified.
- **Credentials, identities, money**, and deleting anything under
  `artifacts/`, `checkpoints/` or `output/`.

## Never touch

- `opencda_marl/_bundled/recordings/*.json` — deterministic traffic replays
  and evaluation ground truth; changing one invalidates every comparison
  made on it.
- `artifacts/_runtime/` — per-cell profiles generated by the matrix
  launcher, gitignored; never hand-edit.
- `.pixi/` and `dependencies/whl/` — the managed environment and vendored
  wheels; everything runs through `pixi run`.
- `artifacts/`, `checkpoints/`, `output/` — run data, possibly the only
  copy; inventory before deleting anything there.
- Any edit under `opencda/` (vendored core) must be recorded in the patch
  ledger (`docs/opencda/marl_patches.md`) in the same commit.

## Quick reference

```bash
pixi run pytest test -q                          # the whole suite; green before any commit
pixi run python -m opencda_marl.plugins    # what is registered, and from where
pixi run python opencda.py -t sumo-marl/intersection/route_speed_only_pcmappo --marl   # SUMO smoke
pixi run -e docs mkdocs build --strict           # after touching docs/ or mkdocs.yml
```

Commits: conventional types, one verified change each, imperative subject.
A change ships with its test; lifecycle, launcher and monitor changes
also get a live smoke run whose counters you actually read.
